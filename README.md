# Quiz Bot — рефакторинг

## Что изменилось

| Было | Стало |
|---|---|
| `bot.py` на ~1500 строк | 11 модулей с разделением ответственности |
| Состояние игр в памяти | SQLite на томе Railway, живёт после редеплоя |
| Google Sheets как база | Sheets — витрина, читается только SQLite |
| Авторизация Google в каждом вызове | Один кэшированный клиент |
| `append_row` в цикле по игрокам | Один `append_rows` на игру |
| Синхронный gspread в event loop | `asyncio.to_thread` |
| Агрегация в Python над всем листом | `GROUP BY` в SQLite |
| Ручной `/quiz` | Плюс автозапуск по расписанию |
| Голые `except:` | Логирование + `add_error_handler` |

## Структура

```
config.py              env-переменные, тайминги, правила начисления очков
texts.py               все тексты сообщений
packs.py               загрузка и валидация пакетов
db.py                  SQLite: схема, запросы, агрегаты
game.py                чистая игровая логика (без Telegram и без БД)
engine.py              оркестрация: регистрация, вопросы, итоги, восстановление
scheduler.py           автозапуск по расписанию
handlers_admin.py      /quiz /pause /resume /abort /schedule /skip /export
handlers_stats.py      /stats /rating /rank /history /games /help
bot.py                 точка входа
migrate_from_sheets.py разовый перенос истории в SQLite
```

## Развёртывание на Railway

1. **Создайте том.** Command Palette (⌘K) → Volume → примонтируйте на `/data`.
   Файлы вне тома не переживают редеплой, поэтому база обязана лежать там.
2. **Проверьте, что реплика одна.** SQLite не шарится между инстансами, да и
   polling у Telegram может быть только один.
3. **Выключите Serverless / App Sleeping.** Планировщик живёт внутри процесса:
   если сервис засыпает, расписание не сработает.
4. **Переменные окружения:**

   | Переменная | Обязательна | Назначение |
   |---|---|---|
   | `BOT_TOKEN` | да | токен бота |
   | `DB_PATH` | нет | по умолчанию `/data/quiz.db` |
   | `GOOGLE_CREDENTIALS` | нет | JSON сервис-аккаунта; без него бот работает, просто без выгрузки |
   | `GOOGLE_SHEET_ID` | нет | ID таблицы |
   | `TIMER_VIDEO_URL` | нет | видео-таймер под вопросом |
   | `T_QUESTION`, `T_BETWEEN`, `LEADERBOARD_EVERY`, `CALIBRATION_GAMES` | нет | тонкая настройка |

5. **Перенесите историю** (один раз, после монтирования тома). Миграция
   запускается локально — `railway run` подставляет переменные окружения в
   ваш процесс, а не выполняет код в контейнере:

   ```
   railway run env DB_PATH=./quiz.db python migrate_from_sheets.py
   sqlite3 quiz.db "VACUUM INTO 'quiz-upload.db';"
   railway volume files upload ./quiz-upload.db /quiz.db
   ```

   Скрипт идемпотентен и ничего не меняет в Google Sheets.
   Подробный порядок действий — в `CUTOVER.md`.

6. **Не деплойте во время квиза.** Редеплой сервиса с томом даёт короткий
   простой; результаты сохранятся, но текущий вопрос оборвётся.

## Расписание

```
/schedule                                   показать слоты группы
/schedule add пн,ср,пт | 20:00 | auto       автовыбор неигранного пакета
/schedule add ежедневно | 19:30 | 0007      фиксированный пакет
/schedule add сб | 18:00 | auto:00 | 90     пул по префиксу, регистрация за 90 мин
/schedule del 3
/schedule on 3  /  /schedule off 3
/skip                                       пропустить сегодняшний запуск
```

Четвёртый параметр — за сколько минут до старта открывать регистрацию
(по умолчанию 60). Время всегда московское.

Планировщик опрашивает расписание раз в минуту и сравнивает текущее время со
слотами — поэтому он переживает рестарт. Защита от двойного запуска —
атомарный `UPDATE last_run_date` в SQLite. Если бот лежал и проспал слот
меньше чем на 15 минут, квиз стартует с сокращённой регистрацией; если
дольше — слот пропускается до следующего дня.

Автовыбор пакета берёт первый ни разу не игранный в этой группе. Когда пул
исчерпан, берётся самый давний и в чат уходит предупреждение.

## Совместимость с лидербордами

Формат листа `Games` сохранён полностью: те же колонки в том же порядке,
время по-прежнему в **сотых долях секунды**. Внутри бота время хранится в
обычных секундах, конвертация происходит только в `sheets._centi()`.

Одно улучшение: блоков «Вопрос N» теперь всегда 16, даже для коротких
пакетов. Раньше при пакете из 12 вопросов колонка «Очки рейтинга» уезжала на
12 позиций влево и лидерборд читал чужие данные.

## Исправленные баги

1. **Сдвиг детализации ответов.** Ответы хранились списком с `append`, а
   читались по индексу вопроса. Пропуск вопроса сдвигал всё последующее.
   Теперь ключ — `(game_id, user_id, q_idx)`.
2. **Процент в `/history`** делился на 100 и показывал «0.8%» вместо 75%.
3. **Гонка на границе вопроса.** `callback_data` содержит номер вопроса,
   поздний ответ не засчитывается следующему вопросу.
4. **Незарегистрированные** получали «Ответ принят ✅», хотя ответ не шёл в зачёт.
5. **Ranking не обновлялся** после игры, только по ручному `/refresh`.
6. **Эвристики «сотые или секунды»** убраны: единый формат хранения.
7. **Лимиты Telegram.** Промежуточный рейтинг раз в 4 вопроса вместо каждого,
   вопросы больше не пинятся (пин остался на регистрации и на победителе).
8. **`/abort` терял результаты.** Теперь сыгранные вопросы сохраняются.
